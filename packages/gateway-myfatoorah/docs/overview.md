# MyFatoorah adapter overview

`@paykernel/gateway-myfatoorah` is a portable `GatewayAdapter<"myfatoorah", MyFatoorahGateway>` for [`createPaymentClient`](../../core/docs/plugin-architecture.md).

- **API base:** sandbox `https://apitest.myfatoorah.com/`; live hosts by portal country (`api`, `api-ae`, `api-sa`, `api-qa`, `api-eg`)
- **Auth:** `Authorization: Bearer <apiToken>` (config `apiToken` is trimmed; whitespace-only is invalid)
- **Surface:** V3 hosted payments (`POST /v3/payments`), V2 inquiry/refund (`GetPaymentStatus`, `MakeRefund`, `GetRefundStatus`), Webhook V2 signatures
- **IDs:** `gatewayId` is the **InvoiceId**. PaymentId (when present) rides `references.relatedIds.paymentId`
- **Customer:** `Customer: { Reference }` is set from `myfatoorahCustomer.reference` when provided, otherwise from `orderId` (`orderId` → `Order.ExternalIdentifier` + `Customer.Reference` so the payment webhook `Invoice.ExternalIdentifier` reliably carries `orderId`). `customerId` is **not** `Order.ExternalIdentifier` and does **not** become `Customer.Reference`.
- **Redirect:** `PaymentURL` → `requires_action` + `redirectUrl`. `callbackUrl` → `IntegrationUrls.Redirection`. **Pending `PaymentURL` cannot be recovered via `GetPaymentStatus` or `GET /v3/invoices/{id}`** — `GetPaymentStatus` has no `PaymentURL` and `GET /v3/invoices/{id}` returns `"No invoices match this InvoiceId"` when there are no transactions (official — https://docs.myfatoorah.com/docs/get-payment-status). Persist `PaymentURL` before ACK; after a crash the redirect is lost — create a new `orderId` for a new invoice. See [Charges](./charges.md#pending-paymenturl-recovery-limit-i1) and [Production checklist](./production-checklist.md).
- **No auth/capture/void:** `capture: false` and `capturePayment` throw `OperationNotSupportedError` (capability `authorization`). `voidPayment` is not implemented
- **Idempotency:** `createPayment` requires a caller `idempotencyKey`, sent as the `Idempotency-Key` header **only in KWT/SAU** (https://docs.myfatoorah.com/docs/idempotency, cached **250 minutes** — after expiry the same key creates a new invoice even in KWT/SAU). Outside KWT/SAU `orderId` or `myfatoorahCustomer.reference` is required; create looks up that `CustomerReference` (not unique — official, returns last invoice per https://docs.myfatoorah.com/docs/payment-inquiry) and reuses a **Paid** invoice only when amount+currency match — `Pending` / amount mismatch / inquiry `5xx`/non-404 `4xx`/empty success `Data` are `indeterminate` with the existing **InvoiceId** when known (no second create); a `429` on the lookup is surfaced as `RateLimitError` with `Retry-After` so callers can back off — see [Charges](./charges.md#rate-limit-on-replay-lookup-i2) and [Idempotency](./idempotency.md). Official 2xx not-found `Message` (empty Data) may create. Unkeyed `/v3/payments` and first `MakeRefund` do not retry `429` (outside KWT/SAU). KWT/SAU skip that preflight. Header-not-supported validation retries once without the header; key conflicts do not. For KWT/SAU post-250-min safety also pass a stable `orderId` and retain the key until settlement. Refunds require the key (`ExternalIdentifier` + `GetRefundStatus` preflight + header only in KWT/SAU; headerless MakeRefund is `retry: false`). `SR`→`SAR` aliased. Any existing `ExternalIdentifier === idempotencyKey` refund is returned before `MakeRefund` (partial-replay safe). **Concurrent refunds with different keys are not provider-deduped — require a caller-side distributed lock per `InvoiceId` outside KWT/SAU** — see [Production checklist](./production-checklist.md) and [Refunds](./refunds.md).
- **Refunds:** MakeRefund is **base currency only** (e.g. KWD), never display/pay (e.g. SAR). Sandbox (`live: false` → `apitest.myfatoorah.com`) base is always `KWD` regardless of `country`; live first-refund base is inferred from `country` (KWT→KWD, SAU→SAR, …) when history is empty, otherwise `KWD`. Results are `refund_pending`, never `completed`. Settlement arrives via `REFUND_STATUS_CHANGED` or `GetRefundStatus` `Refunded`. `PaymentId` on refunds is `ReferencedInvoice.ExternalIdentifier`
- **Amount:** must be `> 0`. JSON amounts are ISO-padded number tokens (`10.50` / `1.200`), never strings — see [Money](./money.md): create/`getPayment` publish **pay** when available, webhooks publish **base**, refunds publish **base**
- **Webhooks:** separate `webhookSecret` (portal secure key), never the API token. Raw string bodies are JSON-parsed before verify; verification fails closed when omitted or secret missing
- **Client types:** `createPaymentClient({ defaultGateway: "myfatoorah" })` types the facade `createPayment` with `MyFatoorahCreatePaymentParams`. Core does not import this package

Do not import this package from `@paykernel/core`.
