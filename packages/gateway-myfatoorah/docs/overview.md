# MyFatoorah adapter overview

`@paykernel/gateway-myfatoorah` is a portable `GatewayAdapter<"myfatoorah", MyFatoorahGateway>` for [`createPaymentClient`](../../core/docs/plugin-architecture.md).

- **API base:** sandbox `https://apitest.myfatoorah.com/`; live hosts by portal country (`api`, `api-ae`, `api-sa`, `api-qa`, `api-eg`)
- **Auth:** `Authorization: Bearer <apiToken>` (config `apiToken` is trimmed; whitespace-only is invalid)
- **Surface:** V3 hosted payments (`POST /v3/payments`), V2 inquiry/refund (`GetPaymentStatus`, `MakeRefund`, `GetRefundStatus`), Webhook V2 signatures
- **IDs:** `gatewayId` is the **InvoiceId**. PaymentId (when present) rides `references.relatedIds.paymentId`
- **Customer:** `Customer: { Reference }` is set from `myfatoorahCustomer.reference` when provided, otherwise from `orderId` (`orderId` → `Order.ExternalIdentifier` + `Customer.Reference` so the payment webhook `Invoice.ExternalIdentifier` reliably carries `orderId`; inbox can correlate via either). `customerId` is **not** `Order.ExternalIdentifier` and does **not** become `Customer.Reference` — see `src/sources.ts:resolveMyFatoorahCustomerReference`.
- **Redirect:** `PaymentURL` → `requires_action` + `redirectUrl`. `callbackUrl` → `IntegrationUrls.Redirection`. **Pending `PaymentURL` cannot be recovered via `GetPaymentStatus` or `GET /v3/invoices/{id}`** — `GetPaymentStatus` has no `PaymentURL` and `GET /v3/invoices/{id}` returns `"No invoices match this InvoiceId"` when there are no transactions (official — https://docs.myfatoorah.com/docs/get-payment-status). Persist `PaymentURL` before ACK; after a crash the redirect is lost — create a new `orderId` for a new invoice. See [Charges](./charges.md#pending-paymenturl-recovery-limit-i1) and [Production checklist](./production-checklist.md).
- **No auth/capture/void:** `capture: false` and `capturePayment` throw `OperationNotSupportedError` (capability `authorization`). `voidPayment` is not implemented
- **Idempotency:** `createPayment` requires a caller `idempotencyKey`, sent as the `Idempotency-Key` header **only in KWT/SAU** (https://docs.myfatoorah.com/docs/idempotency, cached **250 minutes** — after expiry the same key creates a new invoice even in KWT/SAU). Outside KWT/SAU `orderId` or `myfatoorahCustomer.reference` is required; create looks up that `CustomerReference` (not unique — official, returns last invoice per https://docs.myfatoorah.com/docs/payment-inquiry and https://docs.myfatoorah.com/docs/get-payment-status) and reuses a **Paid** invoice only when amount+currency match — `Pending` / `Refunded`/`PartiallyRefunded` / paid-mismatch / missing amount are `indeterminate` with the existing **InvoiceId** when known (no second create); `Canceled`/`Failed` (including `Expired` → `failed`) **allow a new invoice**. A `429` on the lookup is surfaced as `RateLimitError` with `Retry-After` so callers can back off (see `docs/charges.md` I2). KWT/SAU may optionally do a best-effort `CustomerReference` preflight for 250-min hardening — `Paid`+match reuses, otherwise falls through to `POST` without blocking (see `docs/charges.md` I5).
- **Refunds:** MakeRefund is **base currency only** (e.g. KWD), never display/pay (e.g. SAR) — `InvoiceValue` is base per https://docs.myfatoorah.com/docs/get-payment-status; sandbox (`live: false` → `apitest.myfatoorah.com`) base is always `KWD` regardless of `country`; live first-refund base is inferred from `country` (KWT→KWD, SAU→SAR, …) when history is empty, otherwise `KWD` (see `docs/money.md` MF-WEBHOOK-MONEY-DRIFT and MF-SANDBOX-BASE). Results are `refund_pending`, never `completed`. Settlement arrives via `REFUND_STATUS_CHANGED` or `GetRefundStatus` `Refunded`. `PaymentId` on refunds is `ReferencedInvoice.ExternalIdentifier`. `getPayment` is **refund-blind** — after a refund the invoice still reads `Paid`; use `GetRefundStatus` / `REFUND_STATUS_CHANGED` (see `docs/status-mapping.md` I3).
- **Amount:** must be `> 0`. JSON amounts are ISO-padded number tokens (`10.50` / `1.200`), never strings — see [Money](./money.md): create/`getPayment` publish **pay** when available, webhooks publish **base**, refunds publish **base**; `KD`/`SR` and dotted variants aliased to `KWD`/`SAR`; grouping commas `12,345.000` stripped.
- **Webhooks:** separate `webhookSecret` (portal secure key), never the API token. Raw string bodies are JSON-parsed before verify; verification fails closed when omitted or secret missing. `Invoice.Status=PAID` is terminal per https://docs.myfatoorah.com/docs/v3-updating-payment-status-guidelines — mapper `myFatoorahPaymentWebhookStatus` is **stateless**, so consumers must enforce Paid terminal at the inbox (`isMyFatoorahPaidTerminal` / `status === "paid"` + ignore later `pending`/`failed` for same `Invoice.Id`/`ExternalIdentifier`) — see `docs/webhooks.md#paid-is-terminal` and `docs/status-mapping.md`.
- **Client types:** `createPaymentClient({ defaultGateway: "myfatoorah" })` types the facade `createPayment` with `MyFatoorahCreatePaymentParams`. Core does not import this package

Do not import this package from `@paykernel/core`.
