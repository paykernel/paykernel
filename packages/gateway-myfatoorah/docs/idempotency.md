# Idempotency

- **createPayment:** **requires** a caller `idempotencyKey`, sent as the `Idempotency-Key` header **only in KWT/SAU** (https://docs.myfatoorah.com/docs/idempotency — header is omitted elsewhere to avoid a validation rejection). MyFatoorah caches the key for **250 minutes** — replay `createPayment` with the same key after timeout / 5xx / `indeterminate` in KWT/SAU. The adapter does **not** mint a UUID. Create is auto-retried (`withRetry`) when `KWT`/`SAU` (header dedupes); otherwise only before-submit retries, and a post-submit timeout / `afterProviderSubmit` / `indeterminate` **first looks up** `CustomerReference = orderId` (fallback `idempotencyKey`) via `GetPaymentStatus` before replay to avoid double-charge outside KWT/SAU (MF-CREATE-REPLAY). On a 2xx `IsSuccess:false` `ValidationErrors`/`FieldsErrors` `Idempotency` rejection (string-body envelope), create still retries once without the header.
- **refundPayment:** requires `idempotencyKey`, sent as `ExternalIdentifier` and (best-effort) the `Idempotency-Key` header **only in KWT/SAU**. The header is honored in `KWT`/`SAU` only; on a provider `Idempotency` validation rejection (including 2xx string-body `ValidationErrors`) the adapter retries the single request once without the header — `ExternalIdentifier` still carries the key for replay. `MakeRefund` is **not** auto-retried after submit (`afterProviderSubmit`), because `ExternalIdentifier` does not dedupe on the gateway: reconcile via `GetRefundStatus` + the nested-refund key match instead of a second `POST` (preflight). **Any existing refund with `ExternalIdentifier === idempotencyKey` is returned before any `MakeRefund`, even for partial refunds (MF-CRIT-1).**
- Replay protection: a fully refunded invoice maps **only** the nested refund whose `ExternalIdentifier` exactly matches the key; otherwise it throws — never re-POSTs the invoice amount and never maps a single unkeyed refund to an unrelated key. Partial-refund replays with the same key also map to the existing refund before posting. Inquiry `POST`s (`GetPaymentStatus` / `GetRefundStatus`) are not money-mutating and never produce `afterProviderSubmit` / `indeterminate`. `SR`→`SAR` aliased. Create outside KWT/SAU uses the `CustomerReference` lookup above instead of header dedupe.
