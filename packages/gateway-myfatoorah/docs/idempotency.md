# Idempotency

- **createPayment:** **requires** a caller `idempotencyKey`, sent as the `Idempotency-Key` header **only in KWT/SAU** (https://docs.myfatoorah.com/docs/idempotency — header is omitted elsewhere to avoid a validation rejection). MyFatoorah caches the key for **250 minutes** — replay `createPayment` with the same key after timeout / 5xx / `indeterminate` in KWT/SAU. The adapter does **not** mint a UUID. Create is auto-retried (`withRetry`) when `KWT`/`SAU` (header dedupes); KWT/SAU do **not** preflight `CustomerReference`. Outside KWT/SAU only before-submit retries, and a create with `orderId` / `myfatoorahCustomer.reference` **first looks up** that `CustomerReference` via `GetPaymentStatus` (MF-CREATE-REPLAY). Officially that key is **not unique** — only a **Paid** invoice whose pay/base amount matches the request amount+currency is reused. `Pending` falls through (no `PaymentURL`). Inquiry 5xx / 429 fail closed as `indeterminate` instead of creating a second invoice. A “header not supported” validation error retries once without the header; an idempotency **conflict** (same key, different body) does not.
- **refundPayment:** requires `idempotencyKey`, sent as `ExternalIdentifier` and (best-effort) the `Idempotency-Key` header **only in KWT/SAU**. A “header not supported” validation error retries **once** without the header (`retry: false` — no 429 fan-out). Conflicts are not retried. `ExternalIdentifier` still carries the key for replay. `MakeRefund` is **not** auto-retried after submit (`afterProviderSubmit`), because `ExternalIdentifier` does not dedupe on the gateway: reconcile via `GetRefundStatus` + the nested-refund key match instead of a second `POST` (preflight). **Any existing refund with `ExternalIdentifier === idempotencyKey` is returned before any `MakeRefund`, even for partial refunds (MF-CRIT-1).**
- Replay protection: a fully refunded invoice maps **only** the nested refund whose `ExternalIdentifier` exactly matches the key; otherwise it throws — never re-POSTs the invoice amount and never maps a single unkeyed refund to an unrelated key. Partial-refund replays with the same key also map to the existing refund before posting. Inquiry `POST`s (`GetPaymentStatus` / `GetRefundStatus`) are not money-mutating. `SR`→`SAR` aliased. Create outside KWT/SAU uses the `CustomerReference` lookup above instead of header dedupe.
