# Idempotency

- **createPayment:** **requires** a caller `idempotencyKey`, sent as the `Idempotency-Key` header **only in KWT/SAU** (https://docs.myfatoorah.com/docs/idempotency — header is omitted elsewhere to avoid a validation rejection). MyFatoorah caches the key for **250 minutes** — replay `createPayment` with the same key after timeout / 5xx / `indeterminate` in KWT/SAU. The adapter does **not** mint a UUID. Create is auto-retried (`withRetry`) when `KWT`/`SAU` (header dedupes, including `429`); KWT/SAU do **not** preflight `CustomerReference`. Outside KWT/SAU `orderId` or `myfatoorahCustomer.reference` is **required**, only connect-fail retries run (`429` after `/v3/payments` is **not** retried), and create **first looks up** that `CustomerReference` via `GetPaymentStatus` (MF-CREATE-REPLAY). Officially that key is **not unique** — only a **Paid** invoice whose pay/base amount matches the request amount+currency is reused. `Pending`, a Paid invoice with a different amount/currency, inquiry 5xx / 429, non-404 4xx, and `IsSuccess:true` with empty `Data` **fail closed** as `indeterminate` (no second `/v3/payments`). Fail-closed reuse of an existing invoice returns that **InvoiceId** as `gatewayId`. “No invoice yet” is HTTP **404** or HTTP **2xx** `IsSuccess:false` with empty `Data`, no `ValidationErrors`, and an official not-found `Message` (`No data matches this Key` / `not found` / `no invoice`). Generic `IsSuccess:false` does **not** create. A “header not supported” validation error retries once without the header; an idempotency **conflict** (same key, different body) does not.
- **refundPayment:** requires `idempotencyKey`, sent as `ExternalIdentifier` and (best-effort) the `Idempotency-Key` header **only in KWT/SAU**. A “header not supported” validation error retries **once** without the header (`retry: false` — no 429 fan-out). The **first** `MakeRefund` also does **not** auto-retry `429` (`isMyFatoorahRetryableBeforeSubmit` excludes `RateLimitError`). Conflicts are not retried. `ExternalIdentifier` still carries the key for replay. `MakeRefund` is **not** auto-retried after submit (`afterProviderSubmit`), because `ExternalIdentifier` does not dedupe on the gateway: reconcile via `GetRefundStatus` + the nested-refund key match instead of a second `POST` (preflight). **Any existing refund with `ExternalIdentifier === idempotencyKey` is returned before any `MakeRefund`, even for partial refunds (MF-CRIT-1).**
- Replay protection: a fully refunded invoice maps **only** the nested refund whose `ExternalIdentifier` exactly matches the key; otherwise it throws — never re-POSTs the invoice amount and never maps a single unkeyed refund to an unrelated key. Partial-refund replays with the same key also map to the existing refund before posting. Inquiry `POST`s (`GetPaymentStatus` / `GetRefundStatus`) are not money-mutating. `SR`→`SAR` aliased. Create outside KWT/SAU uses the `CustomerReference` lookup above instead of header dedupe.
