# Idempotency

- **createPayment:** **requires** a caller `idempotencyKey`, sent as the `Idempotency-Key` header. MyFatoorah caches the key for **250 minutes** — replay `createPayment` with the same key after timeout / 5xx / indeterminate. The adapter does **not** mint a UUID. Create is auto-retried (`withRetry`) because the header dedupes.
- **refundPayment:** requires `idempotencyKey`, sent as `ExternalIdentifier` and (best-effort) the `Idempotency-Key` header. The header is honored in KWT/SAU only; on a provider validation rejection the adapter retries the single request once without the header — `ExternalIdentifier` still carries the key for replay. `MakeRefund` is **not** auto-retried after submit (`afterProviderSubmit`), because `ExternalIdentifier` does not dedupe on the gateway: reconcile via `GetRefundStatus` + the nested-refund key match instead of a second POST.
- Replay protection: a fully refunded invoice maps the nested refund whose `ExternalIdentifier` matches the key (or a single refund without one); without a match it throws — never re-POSTs the invoice amount.
