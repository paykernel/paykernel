# Idempotency

- **createPayment:** **requires** a caller `idempotencyKey`, sent as the `Idempotency-Key` header. MyFatoorah caches the key for **250 minutes** — replay `createPayment` with the same key after timeout / 5xx / indeterminate. The adapter does **not** mint a UUID. Create is auto-retried (`withRetry`) when `KWT`/`SAU` (header dedupes); otherwise only before-submit retries. On an `Idempotency` validation rejection (unknown header outside `KWT`/`SAU`), create retries once without the header.
- **refundPayment:** requires `idempotencyKey`, sent as `ExternalIdentifier` and (best-effort) the `Idempotency-Key` header. The header is honored in `KWT`/`SAU` only; on a provider `Idempotency` validation rejection the adapter retries the single request once without the header — `ExternalIdentifier` still carries the key for replay. `MakeRefund` is **not** auto-retried after submit (`afterProviderSubmit`), because `ExternalIdentifier` does not dedupe on the gateway: reconcile via `GetRefundStatus` + the nested-refund key match instead of a second `POST`.
- Replay protection: a fully refunded invoice maps **only** the nested refund whose `ExternalIdentifier` exactly matches the key; otherwise it throws — never re-POSTs the invoice amount and never maps a single unkeyed refund to an unrelated key. Inquiry `POST`s (`GetPaymentStatus` / `GetRefundStatus`) are not money-mutating and never produce `afterProviderSubmit` / `indeterminate`.
