# Production checklist

- **Webhook secret:** configure `webhookSecret` (portal secure key) **separately** from `apiToken`. Never use the API token as the HMAC key. Verify before parse (`verifyWebhook`), then inbox-claim, then fulfill. Raw string webhook bodies are JSON-parsed before verify (MF-WEBHOOK-RAW).
- **Fulfill only `paid`:** never fulfill `requires_action` / `redirectUrl` results. Redirect return URLs are browser callbacks, not webhooks — confirm settlement with `GetPaymentStatus` / the signed webhook. `PaymentCompleted: true` without nested statuses is still `paid` (MF-PAYMENTCOMPLETED-REDIRECT); pending invoices stay `pending` even when transaction is `FAILED`/`AUTHORIZE`.
- **Hosts & tokens:** sandbox is `apitest.myfatoorah.com` (currency KWD, no real money). Live uses per-country hosts (`api`, `api-ae`, `api-sa`, `api-qa`, `api-eg`) and a per-country live token.
- **HTTPS callback:** `callbackUrl` and `webhookUrl` must be HTTPS. MyFatoorah rejects localhost.
- **No raw cards:** this backend adapter never sends cardholder data. Embedded sessions use `myfatoorahSessionId`; saved cards use `myfatoorahToken`. Never store PAN/CVC.
- **Idempotency:** always pass a caller `idempotencyKey` on create/refund **and provide `orderId`** (or `myfatoorahCustomer.reference`) for replay safety. On create timeout / 5xx / `afterProviderSubmit` / `indeterminate`, replay with the same key (250-minute cache **in KWT/SAU only** — https://docs.myfatoorah.com/docs/idempotency; **outside KWT/SAU `Idempotency-Key` is omitted** — create looks up `CustomerReference` and reuses only a **Paid** invoice whose amount+currency match; inquiry 5xx/429 is `indeterminate`, not a second create). Outside KWT/SAU without `orderId`/`myfatoorahCustomer.reference` there is no dedupe. On refund submit-timeout, do **not** re-POST — reconcile with `GetRefundStatus` using the same `ExternalIdentifier`. Refund `Idempotency-Key` is KWT/SAU only; headerless retry is once, `retry: false`, and only when the error is “header not supported”.
- **Refund settlement & currency:** MakeRefund acceptance is not settlement. Wait for `REFUND_STATUS_CHANGED` `REFUNDED` (or `GetRefundStatus` `Refunded`) before treating a refund as complete. **MakeRefund amount is account base currency (e.g. KWD), not the currency you charged (e.g. SAR)** — sandbox (`live: false` → `apitest.myfatoorah.com`) base is always `KWD` regardless of `country`; live first-refund base is inferred from `country` (KWT→KWD, SAU→SAR, …) only when `live: true` and history is empty, otherwise `KWD` (MF-SANDBOX-BASE). Pass base explicitly on first refund when histories are empty; the adapter fails closed if you pass `SAR` after `BaseCurrency: KWD` is known.
- **Amounts:** major units, ISO-padded on the wire (`10.50` SAR, `1.200` KWD). Zero amounts are rejected. `SR`→`SAR` aliased. Create `orderId` is sent as both `Order.ExternalIdentifier` and `Customer.Reference` (`Customer: { Reference = orderId }` or `myfatoorahCustomer.reference`; `customerId` is **not** `ExternalIdentifier` and does **not** become `Customer.Reference` — MF-CUSTOMER-REF) so webhooks carry it as `Invoice.ExternalIdentifier` → `paymentId`. See [Money](./money.md): create/`getPayment` publish **pay** when available, webhooks publish **base** (MF-WEBHOOK-MONEY-DRIFT).
