# Production checklist

- **Webhook secret:** configure `webhookSecret` (portal secure key) **separately** from `apiToken`. Never use the API token as the HMAC key. Verify before parse (`verifyWebhook`), then inbox-claim, then fulfill. Raw string webhook bodies are JSON-parsed before verify (MF-WEBHOOK-RAW). `Invoice.Status=PAID` is terminal per https://docs.myfatoorah.com/docs/v3-updating-payment-status-guidelines — mapper `myFatoorahPaymentWebhookStatus` is **stateless**, so enforce Paid terminal at the inbox (`isMyFatoorahPaidTerminal` / `status === "paid"` + ignore later `pending`/`failed` for same `Invoice.Id`/`ExternalIdentifier`) — see `docs/webhooks.md#paid-is-terminal`.
- **Fulfill only `paid`:** never fulfill `requires_action` / `redirectUrl` results. Redirect return URLs are browser callbacks, not webhooks — confirm settlement with `GetPaymentStatus` / the signed webhook. `PaymentCompleted: true` without nested statuses is still `paid` (MF-PAYMENTCOMPLETED-REDIRECT); pending invoices stay `pending` even when transaction is `FAILED`/`AUTHORIZE`. `getPayment` is **refund-blind** — after a refund the invoice still reads `Paid`; use `GetRefundStatus` / `REFUND_STATUS_CHANGED` to observe refunds (see `docs/status-mapping.md` I3).
- **Hosts & tokens:** sandbox is `apitest.myfatoorah.com` (currency KWD, no real money). Live uses per-country hosts (`api`, `api-ae`, `api-sa`, `api-qa`, `api-eg`) and a per-country live token.
- **HTTPS callback:** `callbackUrl` and `webhookUrl` must be HTTPS. MyFatoorah rejects localhost.
- **No raw cards:** this backend adapter never sends cardholder data. Embedded sessions use `myfatoorahSessionId`; saved cards use `myfatoorahToken`. Never store PAN/CVC.
- **Idempotency:** always pass a caller `idempotencyKey` on create/refund **and provide `orderId`** (or `myfatoorahCustomer.reference`) for replay safety. Outside KWT/SAU that reference is **required**. On create timeout / 5xx / `afterProviderSubmit` / `indeterminate`, replay with the same key (250-minute cache **in KWT/SAU only** — https://docs.myfatoorah.com/docs/idempotency; **outside KWT/SAU `Idempotency-Key` is omitted** — create looks up `CustomerReference` and reuses only a **Paid** invoice whose amount+currency match; `Pending`, `Refunded`/`PartiallyRefunded`, paid-mismatch, or missing amount are `indeterminate` with the existing `InvoiceId` when known, not a second create; `Canceled`/`Failed` (including `Expired` → `failed`) **allow a new invoice** with the same `CustomerReference` — retry after cancel/failure. A `429` on the lookup is surfaced as `RateLimitError` with `Retry-After` so callers can back off; other failures remain `indeterminate`. KWT/SAU may optionally do a best-effort `CustomerReference` preflight for 250-min hardening — `Paid`+match reuses, otherwise falls through to `POST` without blocking (see `docs/charges.md` I5 and `local://replay-proposal.md`).
- **Refund settlement & currency:** MakeRefund acceptance is not settlement. Wait for `REFUND_STATUS_CHANGED` `REFUNDED` (or `GetRefundStatus` `Refunded`) before treating a refund as complete. **MakeRefund amount is account base currency (e.g. KWD), not the currency you charged (e.g. SAR)** — `InvoiceValue` is base per https://docs.myfatoorah.com/docs/get-payment-status; sandbox (`live: false` → `apitest.myfatoorah.com`) base is always `KWD` regardless of `country`; live first-refund base is inferred from `country` (KWT→KWD, SAU→SAR, …) only when `live: true` and history is empty, otherwise `KWD` (MF-SANDBOX-BASE). Fixtures use KWD base + SAR pay to lock base-drift. Pass base explicitly on first refund when histories are empty; the adapter fails closed if you pass `SAR` after `BaseCurrency: KWD` is known.
- **Concurrent refunds (I6) — caller-side distributed lock required:** `ExternalIdentifier` is **not provider-deduped** and `GetRefundStatus`→`MakeRefund` has a TOCTOU window. Two parallel `refundPayment` calls with **different** `idempotencyKey` values for the same `InvoiceId` can both observe the same `remaining` and both `MakeRefund`, double-refunding outside KWT/SAU. KWT/SAU `Idempotency-Key` only dedupes the HTTP window, not `ExternalIdentifier`. **Require a caller-side distributed lock (e.g. Redis `SET NX` / DB advisory lock) per `InvoiceId` (or per `orderId`) for `refundPayment` outside KWT/SAU** — hold the lock across `GetRefundStatus`+`GetPaymentStatus`+`MakeRefund` and release after settlement. For the **same** key, the adapter's `GetRefundStatus` preflight (`ExternalIdentifier === idempotencyKey`) is crash-retry safe and prevents a second `MakeRefund` even when `remaining > 0` (MF-CRIT-1), but it does **not** protect concurrent different keys.
- **Pending `PaymentURL` recovery limit (I1):** `GetPaymentStatus` has no `PaymentURL` and `GET /v3/invoices/{id}` returns `"No invoices match this InvoiceId"` when there are no transactions (official — https://docs.myfatoorah.com/docs/get-payment-status). A pending invoice's redirect **cannot be recovered via inquiry**. Persist `PaymentURL` from `createPayment` **before ACK**. After a crash, query `GetPaymentStatus` for status but the redirect is lost — to let the customer pay, create a **new invoice with a new `orderId` / `CustomerReference` value** (new reference, not a replay of the same one). The adapter's pending `indeterminate` with `InvoiceId` lets you `getPayment` to observe status but will never mint a second chargeable invoice on the same `CustomerReference` (except `Canceled`/`Failed` which allow new).
- **Amounts:** major units, ISO-padded on the wire (`10.50` SAR, `1.200` KWD). Zero amounts are rejected. `SR`/`KD` and dotted variants `S.R.`/`K.D.` aliased to `SAR`/`KWD`; grouping commas `12,345.000` stripped. Create `orderId` is sent as both `Order.ExternalIdentifier` and `Customer.Reference` (`Customer: { Reference = orderId }` or `myfatoorahCustomer.reference`; `customerId` is **not** `ExternalIdentifier` and does **not** become `Customer.Reference` — MF-CUSTOMER-REF) so webhooks carry it as `Invoice.ExternalIdentifier` → `paymentId` (either identifier correlates). See [Money](./money.md): create/`getPayment` publish **pay** when available, webhooks publish **base** (MF-WEBHOOK-MONEY-DRIFT); `InvoiceValue` is base per https://docs.myfatoorah.com/docs/get-payment-status.
